## 1. 1_sigint3 — Ctrl+C 세 번에 종료


1번 과제 변경점
``` 1번 과제 / 변경점
1. got_sigint = 0 을 got_sigint_count = 0 으로 변수이름 변경
- 몇 번 왓는지 카운트 하기 위해 변수 이름 알아보기 쉽게 변경

2. 핸들러 got_sigint = 1; 을 got_sigint_count += 1; 로 변경
- 한번 올때마다 횟수를 새게 함

3. while (!got_sigint)     /     while (got_sigint_count < 3) {  
        pause();                     pause();                    
                                     if (got_sigint_count < 3)
                                         printf(...); //횟수출력
                                }
- 3이 될때까지 반복
- pause() 가 돌아온 직후에 횟수를 출력 하도록 함

4. printf("\nSIGINT 를 3회 받았습니다. 정리하고 종료합니다.\n"); 
- 종료 메시지에 몇 회 받았는지 횟수 출력 후 종료하게 함

```

## 2. alarm — N초마다 M번 울리는 타이머


2번 과제 변경점
``` 2번 과제 / 변경점
1. timeout 플래그를 timeout을 올리는 횟수 카운터로 변경
- timeout += 1;로 변경하여 알람이 몇 번 울렸는지 확인하도록 변경

2. 전역 변수 int count , int repeat 추가
- 간격과 횟수를 입력받아야 하는데 핸들러는 값을 받지 못하기 때문에 추가
- 핸들러가 읽어야 하는 값이기에 전역 변수로 함

3. 핸들러에서 timeout = 1;을 timeout += 1;로 변경
- 알람이 울릴 때마다 횟수가 하나씩 증가하도록 변경
- if (timeout < repeat) alarm(count); 를 넣어서 횟수보다 아래일때 다음 알람을 예약

4. main(void)를 main(int argc, char *argv[])로 변경
- atoi(argv[1]), atoi(argv[2]) 로 알람 간격과 반복 횟수를 입력받도록 변경

5. alarm(3)을 alarm(count)로 변경
- 첫 알람 (이후는 핸들러가 처리)

6. fgets() 입력 대기와 alarm(0) 취소 부분을 전부 삭제
- while (timeout < repeat) { pause(); printf(...)} 로 변경
- 입력 제한시간을 설정하는 프로그램이 아니기에 필요없음
```

### 이번 과제를 하면서 이해한 내용

1. **시그널과 핸들러**
   시그널은 커널이 프로세스에 보내는 짧은 알림이고
   핸들러를 등록하면 시그널이 왔을 때 프로그램이 바로 죽는 대신 제가 만든 함수가 실행된다는것을 알았습니다.

2. **핸들러에서 printf 를 쓰지 않는 이유**
   핸들러는 main 이 뭘 하던 중이든 끼어들어 실행됩니다.
   main 이 printf 를 하는 중에 핸들러가 또 printf 를 부르면 꼬일 수가 있기에
   핸들러는 변수만 바꾸고, 출력은 main 에서 한다는것을 알게되었습니다.

3. **volatile sig_atomic_t 를 쓰는 이유**
   volatile 이 없으면 컴파일러가 변수가 바뀌지 않는다고 이해하고 한 번만 읽어서 
   핸들러가 값을 바꿔도 main 이 모르고 무한 루프에 빠질 수 있다는것을 알게 되었습니다.
   sig_atomic_t 는 값을 읽고 쓰는 게 한 번에 끝나서 중간에 끼어들어도 깨진 값을 보지 않는다는것을 알게 되었습니다.

4. **(과제 1) pause() 다음 줄에 printf 를 둔 이유**
   pause() 는 시그널이 와서 핸들러가 끝난 뒤에 실행됩니다.
   그렇기에 pause() 다음 줄은 시그널이 울린 후의 자리라는것을 알게 되었습니다
   그래서 pause() 다음줄에 printf 를 사용하여 횟수를 표시하였습니다.

5. **(과제 2) 핸들러에서 alarm() 을 다시 부르는 이유**
   alarm() 은 한 번만 울립니다.
   계속 울리게 하려면 울릴 때마다 핸들러에서 다음 알람을 다시 걸어야 한다는것을 알게 되었습니다.

6. **(과제 3) 막힌 시그널은 사라지지 않지만 쌓이지도 않는다**
   SIGINT 를 막아 둔 5초 동안 Ctrl+C 를 열 번 넘게 눌러도 꺼지지 않았고 푸는 순간 핸들러가 실행되었습니다.
   막힌 동안의 시그널은 대기하고 있다는것을 알게 되었습니다.
   하지만 "왔다/안 왔다"만 기억하고 몇 번인지는 세지 않아서 횟수를 세게 해보았는데
   막아둔것을 풀면 한 번만 오게 된다는것을 알게 되었습니다.
   
9. **SIG_SETMASK 로 되돌리는 이유**
   SIG_UNBLOCK 은 SIGINT 만 푸는 거라, 원래 막혀 있던 다른 시그널이 있었다면 그대로 둬야된다는것을 알게 되었습니다
